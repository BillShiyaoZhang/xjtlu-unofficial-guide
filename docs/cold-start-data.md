## 查看与复用

```powershell
npm run seed:cold-start -- --check
npm run seed:cold-start -- --batch 2026-09-10-zhitiao.json --check
npm run build:pages
npm run preview:pages
```

打开 <http://127.0.0.1:4318/>，首页“从公开来源整理”可展开更多条目及历史活动，详情展示来源；目录搜索可查找“双选会”“LibAI”“楼层图”等新内容。新增话题与 GitHub 真实讨论分别呈现，不增加参与人数或评论数。

`community/cold-start/2026-09-10.json` 和 `2026-09-10-zhitiao.json` 是两个选定批次，`community/community-topics.json` 是实际构建输入。`npm run seed:cold-start` 默认导入第一批，可用 `--batch 2026-09-10-zhitiao.json` 选择第二批。校验后只追加缺少的稳定 ID；已导入时不写文件；相同 ID 内容被维护者修改后会报冲突，避免覆盖后续修订。它不访问 runtime，也不提交、推送或创建 GitHub Issues。

本地构建和测试预览不会更新线上 Pages。发布本轮内容时，须将话题配置、UI、脚本与测试按正常仓库流程部署；`sync:pages` 只同步既有资料快照，不能替代本轮代码与配置部署。

## 来源与时效

- [候选来源记录](research/cold-start-source-candidates.md) 保留检索与去重依据；批次只保存必要字段和原创概括，没有复制帖子全文、图片、头像、联系方式或互动记录。
- `collection: true` 区分来源整理和原有编辑提问；`sources` 保存可公开字段。`read` 表示本次读到了引用页面，`unavailable` 只保留链接和尝试时间，禁止填写摘要。AI 整理不等于人工核验。
- 两个展览保留 `startsOn/endsOn` 日历日期，结束日含当天，按北京时间进入次日后转入历史；不会补造每日开放时刻。校史征集的日期精度混合，作为资源提问保留原页说明。
- 有具体时刻的活动使用带时区的 `startsAt/endsAt`；计划结束后只表示计划已过，不据预告宣称实际举办。新增活动均未取得明确报名开放依据，因此不显示当前报名按钮。
- 两条校园情况为 `unknown`：官方有入口迁移和领书安排，但尚未验证账户迁移结果、各教材中心实时办理状态。资料读取时间没有代填为确认解决时间。
- 2026–27 第一学期领书和中文课程材料不得跨学期继续当作当前安排。后续补充应按来源更新或转为历史提问；稳定 ID 保留原来的讨论关联。

## 纸条与小红书

再次使用内置浏览器和 web 工具仍未取得纸条分享页正文，随后通过普通 HTTP 读取公开 HTML 与 JavaScript，找到无需认证的详情、最新和热门 GET 接口。用户示例的详情读取成功；普通列表及分区列表只返回旧版升级通知，未作为内容来源。

三页最新和一页热门返回 60 条记录，初步排除 4 条、去重 1 条，得到 55 条本地候选。经编辑筛选，20 条逐一读取详情后整理导入，涵盖 MTH305、APH005、CCT007 组队，e-Bridge 课程单，雅思写作、升学就业、月饼预订、区间车、宿舍、自习、开源工具及兴趣邀约。敏感个人内容、身份资料、联系方式、图片和评论没有进入公开批次；标题均为整理者概括。

只有羽毛球邀约可按原帖“明天晚上”与北京时间的发布时间换算为 9 月 11 日，保留日期精度；其余邀约日程未知，没有补造开始时刻或报名人数。校园情况保留 `unknown`，没有把反馈当作已确认事故或已解决事项。

访问结果保存在 `community/cold-start/source-queue.json`；选中记录的公开链接、时间和内容哈希保存在 `2026-09-10-zhitiao-evidence.json`；二者均不进入 Pages 构建。小红书搜索明确要求登录，按用户选择暂缓。可复用采集器及完整方法见 [纸条抓取记录](research/zhitiao-collection.md)。

## 测试样例

运行 `npm run preview:cold-start` 并打开 <http://127.0.0.1:4319/>，可操作 **10 个合成话题、11 条讨论与 11 条回复**。它覆盖问题与追问、活动报名开放/截止/延期/改期/取消/计划已过，以及校园情况持续/已解决/未知。页面醒目标注测试，输入演练不产生外部投稿。详情见 [测试预览说明](cold-start-preview.md)。

正式 `build:pages` 不携带上述合成样例。批次一致性、重复导入、来源边界、日期与报名状态、浏览器来源链接和移动布局，以及测试预览隔离均有对应检查。

第一批验收记录：302 项 Node 测试、13 项平台契约测试、35 项 Pages 浏览器测试通过；服务端 UI 和 Pages 构建通过。第二批新增了采集边界、限速、去重、响应异常、批次来源及重复导入检查，307 项 Node 测试通过。真实 GitHub 讨论的可达性仍由页面单独报告，不用合成结果掩盖加载失败。
