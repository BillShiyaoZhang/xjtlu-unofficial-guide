# 阶段 1 软件实现说明

更新日期：2026-08-29

## 1. 交付结论

仓库已增加一个可本地运行的阶段 1 Web 应用，覆盖“查找答案 → 查看逐句来源和适用范围 → 反馈/报告 → 编辑复核 → 发布可追溯新版本”的软件闭环。

本次没有部署到 OpenAI Sites，也没有开启公开服务。当前定位是工程预览和本地验收基线，不是已经通过四周试点退出条件的正式产品。

## 2. 设计到实现的映射

| 设计能力 | 当前实现 |
|---|---|
| 公开搜索与话题导航 | 关键词、别名、结构化范围过滤；不使用向量或 LLM |
| 答案卡 | 标题、来源支持的事实句、范围、`as_of`、核验/复核时间、负责人 |
| 来源链 | `ArtifactRevision → EvidenceSpan/LinkCitation → SentenceCitation` |
| 权利边界 | `link_only` 不保存正文、截图或内容哈希；证据片段要求公开摘录权利 |
| 修订与发布 | 不可变修订；发布操作和公开指针在 D1 事务中原子切换 |
| 复核 | 自动逾期警示、编辑待复核队列、争议状态 |
| 纠错 | 匿名二选一反馈、结构化报告、不可枚举的高熵追踪码 |
| 私有研究线索 | 邀请凭证、成年确认、随机研究编号哈希、PII/URL 校验、TTL 清理 |
| 编辑安全 | ChatGPT 身份 + 服务端邮箱白名单、Origin 校验、`If-Match`、幂等键 |
| 紧急处置 | 带理由、版本校验和原子审计的整卡隐藏/恢复；隐藏同时阻断历史页 |
| 审计 | 发布、隐藏、报告/线索处理、敏感队列读取和到期清理均追加记录 |

## 3. 关键实现决策

### 3.1 单应用本地适配

设计文档建议最终使用 Next.js + FastAPI + PostgreSQL。本轮先以 Vinext + D1 完成模块化单体，减少本地原型的运行组件。领域不变量位于 SQL 迁移和服务层，不依赖页面状态，因此后续可以迁移到 PostgreSQL 而不改变公开契约。

### 3.2 公开摘要不绕过引用

编辑器保存的检索摘要不再单独作为公开结论。公开列表使用第一条已引用事实句作为摘要；详情页只在逐句来源区域展示结论，避免把无引用的 `summary` 变成规则旁路。

### 3.3 高影响内容默认关闭

当前只有单层编辑白名单，尚未实现领域审核角色、职责分离和来源权威范围。因此 API 和数据库均拒绝高影响答案发布，而不是仅凭“引用类型”误判为安全。

### 3.4 隐藏不改写历史

答案卡隐藏通过 `workflow_operations` 和受控状态触发器完成：旧修订和审计保持不可变，但所有公开读取立即因为卡片状态而失效。恢复公开同样需要理由、`If-Match` 和幂等键。

### 3.5 私有数据最小化

私有线索不接收附件，不自动抓取 URL，不保存邀请凭证或原始研究编号。到期任务覆盖参与者哈希、背景、正文、URL 和材料关系；维护端点默认关闭，必须显式配置独立密钥。

## 4. 验收边界

软件自动化测试能证明数据库不变量、状态规则、URL/PII 基础校验、不可变修订和原子发布/隐藏。它不能替代以下真实世界验收：内容正确率、来源可访问率、任务完成时间、用户覆盖、维护工时、运营响应和合规确认。

因此当前可以进行本地演示和继续开发，但不能仅凭这份实现宣称阶段 1 产品退出条件已满足，也不应直接进入互联网公开上线。
