## 这次填充的内容

本次按学生实际任务整理公开网页，覆盖苏州工业园区与太仓校园的新生、在校本科生和研究生。内容包括入学、账号、教务、图书馆、语言写作、住宿交通、社团体育、支持服务、交流、实习升学和科研。每篇包含问题、简要答案、适用范围、来源事实、行动建议、注意事项和复核日期。

原有四张演示卡及其来源、修订和引用保留。新增内容已合入 `community/content.json`，并单独生成 `community/handbook/runtime-import.json` 供已有本地库导入。它们使用 `origin: ai_draft`、`demo: false` 和 `reviewStatus: pending-human-review`。`researchedAt` 记录资料读取日期；`verifiedAt` 留空，不能将模型联网检查冒写成人工审核。

首次资料导入时，这批内容作为候选稿保存，GitHub Pages 仅展示四张演示卡。用户随后明确要求将搜集的 69 篇全部公开，现增加 Pages 的资料整理初版收录通道；这项授权不计作人工审核，高影响内容和来源校验继续有效。首次资料整理的验收记录保留在文末，反映当时状态，不代表当前 Pages 收录范围。

## 资料整理初版的 Pages 收录

原有 69 个与本轮补充的 7 个精确修订 ID 均写入 `community/pages.config.json` 的 `collectedRevisionIds`。它们以「资料整理初版」进入公开快照，保留 AI 来源、2026-09-10 的资料读取日期、逐句引用和未人工核验说明；不改写原始 `origin`、不填写 `verifiedAt`，也不生成虚构的审核人或「通过」记录。

`export:pages` 只读本机运行库，在隔离内存中对清单选中的版本执行公开投影，仅允许这些版本的 `ai_draft` 来源，其余高影响内容、来源状态与引用规则仍由 SDK 校验。导出的 `community/pages-reviewed.json` 采用 `mode: public-guide`；`collectedCount` 统计资料收录，`reviewedCount` 统计实际人工审核，两者分别报告。原始运行库和生成手册中的初稿状态保持不变。

后续运行 `npm run sync:pages` 会继续处理这份显式清单。人工审核公开版优先于资料初版；隐藏、来源撤回或后续审核标为「需修改」「待核」「不收录」时移除资料初版。新修订或已有发布历史不会使旧初稿重新公开。未来新增草稿不在此次授权内。修改收录清单需先将配置随代码提交部署，再同步新快照，不能仅修改快照或把收录标为人工核验。具体步骤见 [Pages 同步](github-pages.md#本批-69-篇资料的显式收录)。

当前 `public-guide` 发布快照包含 80 篇：76 篇资料收录、0 篇人工审核、4 篇原有演示。后续同步须等对应 GitHub Actions 部署完成后，公开页面才会更新。

## 来源方法

- 来源类别独立于 AI 写作与人工核验状态：学校官网和已确认身份的学校、部门、学院公众号归「学校官方」；读者或维护者直接提供的内容归「用户提供」；商业公众号、学生网站、外部机构等网上材料归「网络资料」。类别不会让文章自动通过审核。
- `research-*.json` 中的 `sourceCategory` 与 `community/source-overrides.json` 是按精确 URL 维护的分类登记；学校域名可识别，微信公众号必须确认发布方后显式登记。平台不可变来源修订保持原样，由构建、导出和服务端添加公开展示字段。新增或调整分类后需重新导出并部署 Pages。
- 使用学校官网、教务/IT/图书馆公开页、苏州市公共服务与医院官网核对入口和可定位事实。官方新闻用于说明特定时间的变化，历史手册明确保留学年。
- 学生 Wiki 与开源项目只作为非官方资源导航。已标明归档状态与未验证范围，不使用个人评价、排名或未证实传闻来填补事实空缺。
- 同一 URL 去重，逐句记录来源；原页面未给出发布日期则保留 `null`。页面显示的学年、更新日期或页脚版权年不自动变成发布日期。
- 正文读取成功记为 `opened`；抓取失败、仅有搜索摘要或 JavaScript 空壳记为 `search-result-only`。后者保留在来源索引供继续查证，不用作事实句证据。
- 保存短篇重写与链接，不保存网页全文、内部文件、截图档案或学生个人资料。校区/人群通用入口不意味着所有服务自动适用于所有人。

## 编辑输入与生成

五份 `community/handbook/research-*.json` 是当前初稿的编辑输入。每个 source 记录标题、公开链接、发布方、来源类别、页面日期、读取日期、读取状态与定位说明；每个 card 的 fact 必须给出本分组的 `sourceKeys`，advice 可不引用。

```powershell
npm run handbook:build
npm run handbook:check
npm test
npm run build
npm run build:pages
```

构建会验证事实引用、来源读取状态、适用范围和平台数据契约，生成完整正文、覆盖清单、独立导入包，并更新主内容与目录。检查模式验证生成结果和编辑输入一致。它不联网，也不会更新核验日期或操作数据库；需要重新查网页时，应先完成实际资料核对。

**这是首次导入快照生成器。** 本批答案与来源固定为 `-v1` 修订；在本批尚未进入运行库之前，可以修改输入并重建。一旦某个运行库已经导入，同 ID 的内容不能重写；后续应使用平台的追加修订工作流，以新的 revision ID、递增 number 和准确 parentRevisionId 关联旧版，并一次提交完整句子与引用。不能用重新生成的 v1 覆盖既有历史，也不能通过删除数据库解决 `IMMUTABLE`。

## 在现有平台中查看

新建本地演示库时，`npm run dev` 会导入完整种子，仅发布四张历史演示答案。重启不再次导入或发布。已有演示库可通过以下显式命令导入本批候选：

```powershell
npm run runtime -- --demo import community/handbook/runtime-import.json
```

该命令需要演示配置已初始化；只追加内容，不改变发布指针。导入后可在 `/editor` 的「内容审核」页直接浏览候选文章。`coverage.json` 列出每张卡的 entity/revision ID，也可以在修订检查或 `/runtime-editor` 中使用。独立运行环境按 [底座运行手册](platform-runtime.md) 选择自己的 `GUIDE_ROOT` 和导入包；本次未对真实环境执行该命令。

## 逐篇勾选与批量审核

启动本地服务后打开 `/editor`，使用具备 `content_reviewer` 角色的实名审核账户登录，进入「内容审核」。已有的 `content_editor` 账户可以阅读正文和来源，提交审核结果需要审核权限。账户开通与多因素登录方式见 [底座运行手册](platform-runtime.md)。

1. 列表默认显示待审核文章，可按关键词、主题或审核状态筛选，每页显示 8 篇。
2. 展开文章，核对完整正文、适用范围、事实句对应的来源及复核信息。同一页可以同时展开多篇，原站链接在新标签页打开。
3. 逐篇勾选，或勾选当前页；换页及改变筛选时保留已有选择，已选总数包含其他页面的文章。
4. 为已选文章统一应用审核结论和理由，再按需要单独修改某篇。结论包括「通过并发布」「需修改」「待核」「不收录」；每篇都须填写 8–400 字的理由。提交前，侧栏和按钮会显示将立即发布的篇数。
5. 提交本批审核。「通过并发布」在同次提交中发布经过人工确认的新修订；其余结论只保存审核意见。成功后显示实际发布篇数，清空选择并重载当前筛选；待审核列表中的已审核文章会移出，可切换「审核通过」等状态查看保存结果。

已保存记录包含审核人、时间、所审核的准确修订、发布的新修订及意见，意见加密保存。审核记录与发布在同一事务内执行，整批提交要么全部成功、要么全部不写入；若其他人已审核、文章版本变化，或任一篇未满足发布规则，应处理提示后重新核对。网络中断后，保持内容不变再次提交会沿用原请求编号，避免重复保存或再次生成发布修订。

打开来源再返回时，工作台会重新核对会话及版本，仅恢复仍对应同一修订和审核记录的未提交选择与意见。未提交内容只留在当前页面内存；显式刷新工作台、切换工作台页签、重新加载页面或退出会清除，请先提交需要保留的意见。

人工审核人核对原站、范围、措辞和复核责任后，可直接选择「通过并发布」。系统保留原始 AI 草稿，追加新的修订记录此次人工确认；正文与逐句引用沿用所核对的版本，同时记录原始来源类型、原稿修订、审核人及实际审核时间。工作台仍将这类内容标为「AI 辅助初稿，经人工审核确认」，不会冒称全文由人工撰写。发布仍经过既有发布规则；高影响结论不能借此绕过领域审核要求。

新确认版本从实际审核时间起安排下次复核，沿用原有周期并限定在 1–90 天；缺少有效周期时采用 30 天。原始资料收集日期和信息截至时间保持不变，原稿资料说明仍作为历史说明保留。

列表状态来自与当前修订关联的审核记录，不覆盖仓库初始快照中的 `reviewStatus`。本次发布的新修订保留对应的通过记录，之后另行追加的新修订需要重新审核。以前仅保存的「通过」记录不会自动补发；需重新核对并明确提交「通过并发布」。原有发布、隐藏和来源处置工具仍保留，执行结果分别记录。

真正完成人工审核并发布后，当前 Node 服务的读者页立即展示相应修订。本地运行库与仓库中的初始内容快照相互独立；再执行 [Pages 同步流程](github-pages.md#本地审核后同步)，将已审核公开版与仍有效的资料收录版本导出为 `community/pages-reviewed.json`，经 GitHub Actions 构建部署后，公开网站才会更新。未获明确收录授权的草稿、内部意见、账户和运行库不随快照上传。隐藏、撤回或修改内容后，也需再次同步，才能更新 Pages。
