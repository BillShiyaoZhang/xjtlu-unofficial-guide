# 引导与探索体验重构

2026-09-12。本轮针对公开 Pages 读者端，同时同步改善本地运行库读者端的基本查找体验。结论来自现有产品意图、页面结构、真实公开内容、浏览器检查与回归测试；没有将启发式审查当作真实用户访谈或转化率实验。

## 问题判断

界面原先优先邀请用户贡献，却没有先建立阅读价值。新用户面对的第一个决定是“我能分享什么”，而已有的 76 篇公开资料、办事入口和主题目录没有形成清楚的起点。给页面增加一段使用说明不足以解决这个顺序问题。

| 用户当下的需要 | 原来的障碍 | 本轮改动 |
| --- | --- | --- |
| 我是第一次来，不知道这里有什么 | 主视觉和首组卡片都邀请回答；主题入口在页面底部 | 首页用一个问题解释价值，提供可点击搜索示例、真实第一篇推荐和三种情境路线 |
| 我还没有明确的问题，想逛一逛 | 大量平级主题缺少阅读顺序 | 每条路线最多推荐三篇文章，并给出相关主题入口；主题浏览提前，其他主题可展开 |
| 我想解决眼前的一件事 | 空搜索框需要用户自己猜关键词；默认视图不一致 | 目录统一默认列表，明确搜索覆盖资料与来源整理，提供关键词示例与当前筛选说明 |
| 搜不到内容，下一步呢 | 零结果仅提示换词或投稿 | 两种视图共用空状态，支持清除筛选、回到探索或留下问题 |
| 我正在读，怎么判断、接着看什么 | 缺少短摘要与段落导航；继续探索入口在表单后 | 标题后展示已有摘要；正文、来源说明、继续阅读三个导航；最多三篇同主题真实推荐 |
| 我想看看一个话题的内容 | 没有投稿时完整表单排在相关资料前；加载后顺序变化 | 固定相关资料、讨论、分享的阅读顺序，分享默认收起，主动点击后展开并聚焦 |
| 我返回刚才的页面 | 首页和目录入口上下文不清楚 | 保留首页来源、所选路线、返回焦点与滚动；目录继续保留查询、主题和视图 |

## 信息结构与交互

首页依次提供搜索与起点、情境路线、主题浏览、公开来源整理、真实讨论、轻量贡献邀请。三个情境是当前阅读需要，不要求注册、选择身份或完成强制教程。

路线推荐的文章 ID 是编辑顺序，渲染前必须在当前公开快照中解析；被撤回或不存在的文章不会成为链接。同主题的其他已公开文章可以补足推荐，没有资料则明确提示。数量来自真实快照，不显示虚构参与量、热度或个性化推荐。

列表负责快速读标题和摘要；分支图负责进一步查看不同陈述、父子补充和来源关系。分支图及其深链仍可直接使用。首页文章携带 `from=discover`，继续读同主题文章时保持入口；目录的 `query/topic/view` 和话题的 `fromTopic` 继续保持各自上下文。

文章中的 AI 整理／人工核验、适用范围、逐段引用、维护日期和警示继续保留。公开来源的类别不等于人工核验。来源导航使用页面内聚焦和滚动，不覆盖 hash 路由。

话题讨论异步加载后仍会更新阶段和对应整理，但不会移动整个阅读区或重建正在填写的表单。摘要链接或输入框拥有焦点时，推迟替换摘要。发表仍由用户在 GitHub 最终确认，原有本机草稿与回复关联继续使用。

本地读者端只承诺查找当前运行库的已发布内容。它增加了三步阅读说明、catalog 主题快捷入口、列表默认值、搜索重置和 URL 恢复，没有照搬公共端的内容数量或 GitHub 社区承诺。编辑工作台、账号、研究同意与发布逻辑保持原有行为。

## 视觉与无障碍

- 用深绿色搜索区与浅色起点卡明确第一步，情境选择区显示当前选择和可阅读的具体标题。
- 手机保留搜索、第一篇和三条路线，压缩说明文字；导航保持可触达，页面不依赖横向拖动。
- 主题入口、搜索示例、路线和阅读导航均可用键盘操作；路线用 `aria-pressed` 表达选择，切换结果通过状态区宣布。
- 保留跳到正文、可见焦点、返回焦点；正文／来源／继续阅读的滚动位置为固定导航留出间距。
- 分享与版本记录采用原生 `details`，无需弹窗教程或额外账户状态。

## 验证与后续观察

- `npm test`：307 项通过。
- 公共浏览器四套：40 项通过，覆盖桌面与 390px 手机、首次访问、三条路线、真实与缺失推荐、查询恢复、空结果、文章来源与下一篇、折叠草稿，以及原有社区、活动和投稿行为。
- 本地分支浏览器测试覆盖默认列表、显式分支、独立陈述、历史版本，以及新增的目录恢复与查询一致性。
- 两种构建均通过：`npm run build`、`npm run build:pages`。
- 浏览器目视核对首页和文章手机布局、固定导航与段落跳转。公共浏览器套件共享构建目录，脚本改为串行执行，避免读取尚在写入的测试资产。

本轮完成的是可运行的引导路径，不预先宣称用户留存或参与率已提高。后续可让首次接触的同学分别完成“找到入住检查”“找到报修入口”“发现一个校园机会”“查不到时换条路径”，观察是否需要口头提示，再根据实际障碍调整起点和推荐顺序。

修改已在本地构建和预览，公开站点需经仓库原有 GitHub Pages 部署流程更新。
