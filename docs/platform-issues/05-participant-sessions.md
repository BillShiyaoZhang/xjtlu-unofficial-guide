# [Platform] 支持参与者凭据与会话生命周期，按操作区分认证保证级别

## 背景和本次验收

指南希望只保留数据、业务规则、小型 SDK 适配及必要页面，把通用存储、身份、授权和生命周期交给平台。

本次已验证 `a436f19` 上的本地未提交 runtime 0.1.1 工作区：上游 `npm test` 87/87 通过，指南两项独立回归 2/2 通过。#4 的 link-only 到期和 #6 的私有快照结果校验均已修复，不再作为阻塞。本次读取的远端 main 仍为 `a436f19`；以下引用指向该提交中尚未改变的身份契约。

继续映射实际用户流程时，发现另一项尚未承接的边界：现有指南将一次性邀请参与者与具名 MFA 编辑明确分开。参与者线下核验资格后兑换邀请，提交私有线索、查看本人处理状态、退出单设备或撤回同意；不会被要求注册具名密码/TOTP 账号。匿名隐私问题报告也是现有的受限安全入口，不等于开放匿名 UGC。

这项是平台适配需求，不是声称现有 MFA 实现有漏洞，也不是要求弱化编辑认证。

## 当前可确认的限制

- [auth.mjs](https://github.com/BillShiyaoZhang/decentralized-information-community/blob/a436f19e60cb8c395a2c3e986e20d4c4d001b931/packages/runtime/auth.mjs#L142) 的 `requirePermission` 无论权限为何，首先要求 `mfa === true`。只有 `lifecycle:self` 的可信邀请主体也无法使用受保护 HTTP 命令。
- `auth.provider.authenticate(state, token, { now })` 仅覆盖验证。HTTP 的普通 logout/revoke 使用内置身份模块；生命周期撤回也只更新 `state.modules.auth.sessions`。不存在受支持的自定义会话签发、单设备退出、全主体撤销与撤回衔接契约。
- 配置 `extensions` 装载的是状态模块、迁移和验证，不是凭据/会话提供方；标准 CLI 也未装载自定义身份提供方。SDK 可以自建服务，但仍需要使用方自己实现凭据、会话和撤销机制。
- `/api/private/list` 是管理者列表，没有本人状态列表；`/api/public-results` 仅覆盖已关联公开内容的配置结果，不能替代本人尚待处理、未关联内容的活动状态。此处只需要本人摘要，不要求参与者读取私有正文。

## 合成探针

在内存 RuntimeStore 上配置 `participant: ['lifecycle:self']`，用可信测试 provider 返回稳定主体 `{ id: 'synthetic-participant', roles: ['participant'], mfa: false }`。这只是模拟已经验证的邀请会话，不接受客户端提交 principal，也没有真实参与者数据。

观察结果：

| 调用 | 结果 |
| --- | --- |
| 邀请主体 POST `/api/private/command` create | 401 `UNAUTHENTICATED`，需要具名 MFA。 |
| 无登录 POST 同入口提交配置的 privacy_report | 401，没有单独受限的匿名报告契约。 |
| 即使测试主体带 MFA，仅持 `lifecycle:self` GET `/api/private/list` | 403 `FORBIDDEN`。 |

SDK `consent/create/withdraw` 本身可以在可信事务中操作稳定非 MFA 主体。因此并非“任何实现路径都不可能”：指南可以保留旧服务或新写完整包装器。但那仍把邀请凭据哈希、会话签发/验证、安全 cookie 或等价传输、重放限制、退出/撤销及在途写入一致性留在业务 repo，没有完成通用机制分离。把邀请主体标成 `mfa:true` 也不是可接受适配。

现有 lifecycle create 已按 withdrawnAt/consent epoch 拒绝撤回主体继续写入；本需求关注外部会话自身的完整生命周期，并未发现对现有撤回检查的绕过。

## 请求的通用契约

1. 提供可选的参与者凭据/会话模块，或完整可消费的 provider 生命周期接口。平台管理凭据与会话的安全生成/验证、期限、重放约束、单设备退出及主体撤销；使用方传入审核后的业务资格和策略，不要求平台识别校园研究名词。
2. 按主体能力和操作声明所需认证保证级别。严格维持编辑发布、账号管理、私有队列管理的 MFA 要求；允许明确配置的参与者 self-service 操作使用独立、可撤销的邀请身份。不能全局关闭 MFA，也不能让参与者获得管理权限。
3. 会话 provider 与生命周期同意/撤回使用同一可验证边界：撤回后旧凭据、所有设备和先上传后提交的请求不能继续写入，退出单设备不等于撤回同意。恢复旧备份不能复活已撤销参与者。
4. 提供按当前主体读取本人状态摘要的受支持入口，并执行所有权、过期和撤回过滤；不输出他人记录或内部备注，不要求开放正文解密。
5. 明确受限匿名隐私报告的接入方式：只能创建配置允许的最小报告 DTO，可配限流/幂等和高熵状态回执，不授予通用私有读写、编辑能力或公开投稿能力。可作为通用受限命令策略或受支持扩展，不要求另建匿名账号体系。

允许提供等价方案或一个打包消费者例子，证明不需要在指南继续维护另一套通用身份与会话实现。

## 验收与范围

- 邀请凭据单次兑换、过期/撤销、设备退出、多设备主体撤回及在途请求竞争均有回归。
- 非 MFA 参与者只能执行配置允许的 self 操作；编辑和管理动作仍拒绝，不能靠提交角色/MFA 字段升级权限。
- 本人活动列表不能横向读取他人记录，未关联公开内容的待处理记录也可按授权返回摘要。
- 匿名隐私报告不要求先加入研究，不泄露私有列表或内部备注；其他匿名写入默认拒绝。
- provider 模式与内置模式的退出/撤销/恢复语义有一致的测试，失败事务不部分提交。
- 独立消费固定 runtime 包，业务配置和少量页面能走通这条身份路线。

成年核验标准、研究编号/渠道、邀请资格、同意文本与版本、试点窗口和统计口径仍由指南维护。本请求不要求把校园产品搬入平台，也不把 UI 字段转换、六种角色名称或 D1 在线驱动列为平台阻塞。
