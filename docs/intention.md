西浦的各类信息分散在不同来源、时间的信息中。它们可信度高低不同，信息有效期不同，互相之间难以交叉比对。

目前能想到的信息来源：
* 学校官网
* 学校邮件
* 各组织平台微信公众号
* 同学们的八卦、评论
除了用户直接提供的信息以外，其他的可以后续再考虑怎么自动化接入进来。

也许我们可以构建一个本体，用来分类这些信息的内容。
比如，本体可以覆盖以下内容：
* 学校、校区、学院、专业、教职工、学生、社团、课程
* 教培机构

平台可以自动录入一些信息，也可以允许用户自己录入。这些信息会按照本体抽取成知识图谱。如此，对于同一件事情，就有了多来源的信息交叉比对。

信息应该与来源、时间对应，这样大家能够根据发布源、发布时间来自行判断信息可靠程度。平台也可以利用大模型等技术对信息进行整合。

我们或许应该允许用户对信息进行评论，以表达多种观点，以及帮助对信息可靠性进行修正。为此，我们因该引入信息版本控制（类似 git）。一方面这有助于记录用户贡献，一方面这也有助于追责。

平台应该允许用户进行实名认证，并为实名认证用户提供徽章标记。这样的徽章有助于分辨由用户信息的可信度。
徽章可以包括：在读年级（大一、大二、大三、大四、硕士、博士），教师，行政，校友（入学年份），组织机构，校外个人。

认证方式可能可以如下：
* 所有人（校外个人）：身份证、手机号，或者看看能不能接入中国政府提供的认证平台更好（我记得好像专门开发了一个）
* 组织机构：联系客服
* 学生、教职工：id 卡图片上配有 “仅限 xx 平台身份认证使用”
* 校友：同上，或者 ebridge

信息的形式：有文字、图片、视频、音频，原始内容可能来自不同平台（考虑到平台政策，可能有的内容只能以链接形式引向原文）

用户使用平台的方式：
* 检索话题 -> 返回这个话题（以及根据知识图谱获得的子话题）中的内容 -> 如果系统没有检索到相关话题（或用户觉得是不同话题），可以生成新话题，话题名称及标签请用户确认
* 发布信息 -> 如果系统没有检索到相关话题（或用户觉得是不同话题），可以生成新话题，话题名称及标签请用户确认
          -> 如果有相关话题，请用户确认加入话题
* 浏览话题 -> 点进某个话题后，先看到话题摘要。然后可以看到对于该话题的统计信息（意见分成几类、每一类的占比、总参与人数等），统计信息的统计时间段有默认值、也可以用户调整。用户可以继续按意见分类或时间顺序查看详细信息。
* 在话题中提问 -> 新建一个话题或打开一个已有话题，在其中添加提问 -> 系统首先检索是否有相关内容，用户确认后发布提问
* 回答提问 -> 回答内容作为信息进入话题
* 对信息进行评价打分 -> 信息的可靠性将综合多种因素：其他信息的一致性、用户评分、评分用户的信用

总结：
* 一个用本体、知识图谱、大模型等技术规范聚类的校内知乎
* 引入用户信用与信息可靠度评分机制
* 旨在提供更可靠的信息
